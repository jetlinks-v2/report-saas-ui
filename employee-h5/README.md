# 报事报修员工 H5

独立 Vue 3 / TypeScript / Ant Design Vue 应用，参考 `tongyi/src/subPages/report-issues-and-repairs` 的员工流程，以当前 SaaS 报修后端为唯一业务事实来源。PC 和 H5 使用同一租户、业务应用、业务项目和工单；H5 不保存第二套业务数据，不接旧认证中心、业主房屋系统或外部设施台账。

页面按手机使用设计：工作台展示可钻取的报事数据；工单池按状态查询，个人相关记录独立筛选；详情展示工单、历史处理和审核，并承接发起、派单、接单、跟进、完成、转派、延期、废弃、回访、评价和有偿签字。表单字段、显示开关、字典及候选人员读取现有项目配置。查验与装修、独立业主登录和外部开放接口沿用既有延期范围。

会话使用项目内应用账号认证取得的运行端身份；登录请求不带旧会话、租户或应用头，通过 `X-Tenant-Domain` 和 `X-Asset-Scope: business_application:<applicationId>` 激活应用范围。每个标签页单独保存会话，退出和401清理当前会话。接口的认证、角色和 AssetsHolder 权限由服务端判断。后续 App 通过受限来源的消息传入 SaaS 会话，不能信任客户端声明的角色或组织。

三个清单使用同一工单数据和读取范围，职责分别为：

- **工单池**：权限范围内全部工单，状态页签仅添加标准 `status` 条件，不按责任人收窄。业务项目和关键词继续作为额外筛选。
- **我的待办**：`id / repair-todo / <type>`，`-1` 为全部待办，`6/7/1/8/9` 分别表示待接单、待跟进、处理中、待回访、待审核。接单匹配当前责任人或角色候选池；跟进匹配当前责任人；回访匹配当前有效流程角色，无角色时回退责任人；审核匹配所有类型待审申请的角色，包括延期、非关、废弃、等级变更及归档。待审核是任务类型，不要求工单主状态为9。废弃审核中的工单不进入接单、跟进、回访待办。所有分支都要求有效员工、相应动作及工单保存权限，并与外层读取范围相交。
- **与我相关**：`id / repair-related / true`，只保留本人登记、当前或历史责任人、过程参与人，不因拥有接单或回访候选角色而加入。历史关系不会授予操作权。

接单、转派、审核和归档后，刷新清单按当前状态重新计算；已归档记录保留在有权查看的相关记录中，不属于待办。三个集合允许自然交集，例如本人当前负责的工单同时属于相关记录和待办。历史工单读取权限随业务项目组织的新层级变化。底部导航提供三类清单，首页和列表右上角保留发起报事入口。

实现与验收：先核对旧员工页面和当前 API，完成会话/基础资料/列表详情，再接通全部动作和附件，最后以手机浏览器与真实后端验证 H5 发起→PC处置、PC发起→H5处置、审核拒绝重提、有偿签字、跨组织授权及无权拒绝。已有 HTTP、SQL 和访问日志覆盖链路；H5 无后台队列或新增 MBean。不会为本地验证改动旧项目源码。

## 应用账号登录

登录只有“项目编码 + 应用账号 + 密码”一个入口。项目编码为空白文本框，由用户手动填写，不内置项目列表、不读取站点配置预填。与 PC 应用链接一样，完整应用账号原样提交到运行端 `/authorize/login`，复用运行端密码加密及验证码配置，不经过 SaaS 主账号登录和控制台项目切换。

登录成功后，使用用户填写的项目编码及站点的报修应用 ID，按 `X-Tenant-Domain`、`X-Asset-Scope` 调用 `/authorize/me`。服务端验证租户、应用成员及角色权限，必须具有报修查询权限才能保存会话和进入 H5。有效项目账号但未加入该报修应用时同样不能进入。独立站点仍对应一个报修应用；手动输入其他项目编码不会自动选择其他报修应用。

会话按标签页保存。旧版 SaaS 主账号登录缓存不再复用，更新后需要以应用账号重新登录。账号是否存在、是否启用及所属项目以系统设置人员和应用成员配置为准；SaaS 主账号本身不代表有同名应用账号。

## 本地启动

需要 Node.js 22.18+、Docker，以及已运行的 Cloud 2.20 网关、认证、文件服务、运行端和报修后端。员工 H5 由本目录独立构建，PC 报修页面位于本仓库根目录，并由 Cloud 主工程以 `modules/report-repair-ui` 接入。

在本目录执行：

```sh
npm ci
npm run build
```

保持在本目录执行：

```sh
docker compose -f compose.yml up -d --build
```

电脑入口为 `http://localhost:9300/`；手机连接同一局域网后，使用电脑局域网 IP 加 `:9300`。H5 的 `/api` 经 Nginx 转发到同一 Cloud 网关，浏览器无需直连报修服务 8506，也无需跨域。开发模式可在本目录执行 `npm run dev`，代理配置见 `vite.config.ts`。

运行配置为 `public/config.json`，以只读文件挂载进容器，更新后刷新页面即可：

- `applicationId`：该 Cloud 项目内的报修业务应用 ID，本机为 `2117203860047114240`。它不是业务项目 ID。
- `apiBase`：运行端同源接口前缀，本机为 `/api`。
- `allowedHostOrigins`：未来嵌入时可交接会话的宿主来源；独立密码登录无需宿主。原生 App 的实际适配仍待后续接入。

登录页仅提供项目编码、应用账号和密码。项目编码手动填写，应用授权全部通过后才保存运行端会话。验证码和密码加密复用运行端配置；服务端要求验证码时必须完成验证。登录与报修 API 共用 `/api` 运行端代理。

## 后续嵌入的会话交接约定

当前已验证浏览器 iframe 宿主交接。H5 完成配置加载后，向 `allowedHostOrigins` 中的父页面发送 `{type: 'jetlinks.repair.ready', nonce, applicationId}`。宿主取得当前 SaaS 会话后，回传 `{type: 'jetlinks.repair.session', nonce, session}`，其中 `session` 为 `{token, tenantDomain, applicationId}`。H5 只接受当前父窗口、配置来源、当前 nonce 和相同项目/应用的消息，再调用真实后端确认应用权限。

以下是宿主侧通用接线示例，`loadSession` 由未来 Cloud App 适配层提供，返回该报修应用的 SaaS 会话；它不是已存在的 Cloud SDK 方法。先注册监听，再设置 iframe 的 `src`：

```js
function connectRepairFrame(frame, h5Url, loadSession) {
  const h5Origin = new URL(h5Url).origin
  const receive = async (event) => {
    if (event.source !== frame.contentWindow || event.origin !== h5Origin) return
    if (event.data?.type !== 'jetlinks.repair.ready') return
    const session = await loadSession(event.data.applicationId)
    frame.contentWindow.postMessage({
      type: 'jetlinks.repair.session',
      nonce: event.data.nonce,
      session,
    }, h5Origin)
  }
  window.addEventListener('message', receive)
  frame.src = h5Url
  return () => window.removeEventListener('message', receive)
}
```

令牌不进入 URL。当前浏览器桥仅接受父窗口，不暴露原生全局登录函数；原生 WebView 的具体消息通道需按后续 Cloud App 的宿主能力接线，不能直接沿用旧认证中心令牌。独立 H5 密码登录与该桥接互相独立。
